## 已确认的决策
- 技术栈：Vite + React + TS + **LESS**（用户明确要求加 LESS）
- **LESS 定位：只做 mixin、嵌套、结构组织与编译期复用；颜色/圆角/字号一律走 CSS 变量，不用 LESS 变量承载主题**。依据是 antd v4 → v5 → v6 的演进（LESS 无法做运行时主题，v6 最终形态是"静态 CSS + CSS 变量"）

- 命名：包名 `ls-design`，类名前缀 `ls-`，CSS 变量前缀 `--ls-`
- 三层令牌：基础令牌 Primitive → 语义令牌 Semantic → 组件令牌 Component

## 派生色方案（已定）
用户选定：**JS 侧用 `@ant-design/colors` 的 `generate()` 预生成 10 级色阶，注入 CSS 变量**，而非 `color-mix()` 运行时派生。

- 接口：`generate(color)` 亮色；`generate(color, { theme: 'dark', backgroundColor: '#141414' })` 暗色
- 索引约定：`colors[5]` = 基色（亮色下），antd MapToken 映射为 bg=1 / border=3 / hover=5 / base=6 / active=7
- 只对品牌色运行时生成；功能色（success/warning/error）用 `presetPalettes` / `presetDarkPalettes` 在 LESS 里编译期固化；info 复用品牌色阶
- 命名：色阶 `--ls-{primary|success|warning|error}-1..10`；语义层静态引用色阶
- 必须做首屏兜底：色阶结果缓存进 localStorage，index.html 防闪屏脚本直接回填，避免无色/闪烁

## TailwindCSS：只进应用层，不进组件内部（本轮实测结论）
用户要求"样式可以用上 tailwindcss"。实测（临时工程 /tmp/tw-probe，tailwindcss + @tailwindcss/vite 4.3.3 + vite 8.3.4 + less 4.9.1）：

**版本事实**
- `@tailwindcss/vite@4.3.3` peer 为 `^5.2.0 || ^6 || ^7 || ^8` → **Vite 8 受支持，无需降级**（网上有 2026 初的文章称只支持到 Vite 7，已过期）
- Tailwind v4 是 CSS-first：无 `tailwind.config.js`，配置全在 CSS 里（`@theme` / `@custom-variant` / `@source` / `@utility`）

**实测行为矩阵**
| 场景 | 结果 |
|---|---|
| `.css` 中 `@apply` 且无 `@reference` | ❌ **构建失败**：`Cannot apply unknown utility class` |
| `.css` 中 `@reference "./main.css"` + `@apply` | ✅ 生效 |
| `.less` 中 `@apply`（加不加 `@reference` 都一样） | ❌ **静默失效**：构建通过，`@apply` 原样进产物，仅 minify 阶段给一条 warning |
| `.less` 中 LESS 嵌套 + `var(--ls-*)` | ✅ 正常 |
| `@theme inline` 映射 `--ls-*` | ✅ 工具类产物为 `var(--ls-color-primary)`，**保留变量引用**，主题切换可穿透 |
| `@custom-variant dark ([data-ls-theme=dark])` | ✅ `dark:` 变体正常生成 |
| `@source "../src/**/*.less"` | ✅ 能扫描 .less 内的类名 |

**结论（架构决定）**
- Tailwind 只用于：Demo 页 / 文档站 / 消费方业务应用
- **组件内部（`src/components/**`）保持 LESS + `var(--ls-*)`，禁止 Tailwind**。三条理由：① v4 不扫 node_modules，组件库作为 npm 包分发会让消费者必须配 `@source`，否则"装了但全是裸样式"；② Tailwind 自带 Preflight 会重置宿主全局元素，组件库越界；③ 工具类是堆叠式，消费者覆盖样式需 `tailwind-merge` 运行时依赖，而组件令牌 `--ls-btn-*` 改一个变量即可
- 桥接点只有一处：`@theme inline { --color-ls-*: var(--ls-color-*) }`。**`inline` 修饰符是命门**，不加会变成编译期快照，主题切换失效
- 用 `@theme { --color-*: initial }` 清空 Tailwind 默认色板，强制只能用自己的令牌

**必须写进 README 的纪律**
1. `.less` 文件里禁止写 `@apply`（静默失效，最危险）
2. `.css` 里用 `@apply` 必须同文件加 `@reference`
3. 库构建不得把 Tailwind 打进 `ls-design.css`

### 本轮实测出的新事实（重要，与之前的推断不同）

**1. ⚠️ LESS 的 `additionalData` 注入路径必须是绝对路径**
`@import (reference) "mixins/index.less"` 会失败：LESS 解析 `@import` 是相对**导入方文件**，于是 `src/icons/Icon.less` 被解析成 `src/icons/mixins/index.less`，报 `'mixins/index.less' wasn't found`。改为 `fileURLToPath(new URL('./src/styles/mixins/index.less', import.meta.url))` 后通过。排除自身也从 `filename.includes(...)` 改为 `filename === MIXINS_ENTRY`（includes 会被同名深层文件误命中）。

**2. ❌ 修正硬性约定 #4：「LESS 变量与 CSS 变量成对产出」不成立**
实测：
```less
.var(@n; @v) { --ls-@{n}: @v; @ls-@{n}: @v; }
.a { .var(color-text; rgba(0,0,0,.88)); }
.b { color: @ls-color-text; }   // ✗ variable @ls-color-text is undefined
```
mixin 内定义的 LESS 变量**不会外泄到兄弟作用域**，同一作用域内还要求调用早于使用。结论：**令牌唯一载体是 CSS 变量**，组件里的编译期算术一律走 `calc()` 组合 CSS 变量（如 `paddingInline = calc(var(--ls-padding-content-horizontal) - var(--ls-line-width))`）。附带好处：值只在运行时解析，天然跟随主题与品牌色。

**3. antd 的两汉字补偿（`two-chinese-chars`）实际不生效**
antd v6 的空格在**渲染阶段**就插入了（`needInserted` 参与 `spaceChildren`），所以首帧后 `buttonRef.textContent` 读到的是「确 定」（3 字符含空格），而 `isTwoCNChar` 只匹配「恰好两个汉字」→ effect 永远把 `hasTwoCNChar` 判为 false → `-two-chinese-chars` 类加不上，`letter-spacing: 0.34em` 补偿规则是死代码。
**真正产生视觉效果的是那个被插入的空格。** 本库照抄 DOM 且逐条对齐 CSS，所以结果一致（happy-dom 实测已确认类名确实未出现）。处理方式：保留 effect 与补偿类，不"修"antd，只加注释说明——将来 antd 若修掉时序问题，我们会自动一起对齐而不是先跑偏。

**4. `loading.delay` 的语义是「跃迁才计时」**
初始 state 直接取 `loadingConfig.loading`，所以**初次挂载即为 loading 时立即转圈、不等延时**；延时只作用在「非 loading → loading」这一跳。与 antd 一致（antd 初始值也取自入参）。冒烟测试最初按"挂载即延时"写，是**用例写错**而非实现错。

**5. antd Button 组件令牌的推导公式（逐条核对 `button/style/token.js`）**
- `paddingInline = paddingContentHorizontal - lineWidth` = 16-1 = **15**；`paddingInlineLG` 同值（不是 23）；`paddingInlineSM = 8 - lineWidth` = **7**（字面量 8，不随密度变）
- `buttonPaddingVertical` 三档**全为 0**（`padding: 0 15px`，高度由 `height` 决定）
- `contentFontSizeSM = fontSize` = **14**（小号按钮文字不缩小！只有高度/内边距/圆角变小）；`contentFontSizeLG = fontSizeLG` = 16
- `iconGap = marginXS` = 8；`onlyIconSize = 'inherit'`
- `defaultShadow = 0 2px 0 controlTmpOutline(=colorFillQuaternary)`；`primaryShadow = 0 2px 0 controlOutline`；`dangerShadow = 0 2px 0 colorErrorOutline`
- `solidTextColor` 亮色 `#fff` / 暗色 `#000` —— 与 `colorTextInverse` 完全同值，直接复用后者
- 危险**填充**态 hover 用 `colorErrorBgFilledHover`（#ffdfdc / #441e1f），**不是** `colorErrorBgHover` —— 两者不同名也不同值，极易抄错
- 三处空转变量的确认：`dashedBgDisabled` ≡ `defaultBgDisabled` ≡ `colorBgContainerDisabled`；default 色块里重赋的 `bg-color-container` ≡ 初值；`--btn-border-color-disabled` / `--btn-text-color-disabled` **被赋值但从不被读取**。本库跳过这三个，跟随 antd 的行为而非其代码形状。
- 变体只在 **solid / outlined / dashed** 三种上投射 `box-shadow`，**filled / text / link 没有阴影**。

**6. `controlOutline` / `colorErrorOutline` 是 `getAlphaColor(bg色, 容器底色)`**
不是简单 alpha 混合：`getAlphaColor(#e6f4ff, #ffffff)` = `rgba(5,145,255,0.1)` —— RGB 不是主色本身（22,119,255），而是"反向求解出的饱和外推色"。算法是从 α=0.01 起以 0.01 步长找第一个让三分量都落回 [0,255] 的 α，**必须同序同精度**，否则视觉等价但字符串不同、无法 diff 回归。已在 `src/utils/color.ts` 复刻并四值校验通过（亮暗 × 主色/错误）。

**7. 暗色 `--ls-primary-6` ≠ 传入的品牌色**
`generate('#1677ff', { theme:'dark', backgroundColor:'#141414' })[5]` = `#1668dc` ≠ `#1677ff`。这是 antd 算法本身的行为（亮暗色阶在各自背景下做了感知校正），不是实现偏差，已在 palette.less 文件头写明。

**8. 环境事实**
- antd 有 `lib/`(CJS) 与 `es/`(ESM) 两份。**`es/` 是无扩展名 import，Node 直接跑会 `ERR_MODULE_NOT_FOUND`**；探测脚本必须用 `require('antd/lib/...')` 走 CJS 解析。`prepareComponentToken` / `prepareToken` 在 `antd/lib/button/style/token.js`。
- `@ant-design/icons-svg@4.6.0` 的 `asn/*.js` 是纯 JSON 形状，可直接抄 `viewBox` + `path[].d`，零运行时依赖。viewBox 有两种规格（`0 0 1024 1024` 与 `64 64 896 896`），**不要统一**，否则图形在 em 框内的视觉大小会变。
- TS 7 环境下 Storybook 必须显式 `typescript.reactDocgen: 'react-docgen'`；`react-docgen-typescript` 依赖 TS 的 JS Compiler API（TS 7 已移除），会导致 props 表**静默变空**（不报错）。
- 无浏览器时验证 React 组件库的可行路径（本轮已跑通）：`createRequire('/Users/lishun/.workbuddy/binaries/node/workspace/package.json')` 解析 happy-dom（装在该隔离工作区，不污染项目）→ 装全局量（`navigator` 在 Node 22 只有 getter，须 `Object.defineProperty`；并设 `IS_REACT_ACT_ENVIRONMENT = true`）→ `vite.createServer({ middlewareMode:true })` + `ssrLoadModule()` 加载 TSX → `react-dom/client` 真渲染 + `act()` 刷 effects。
